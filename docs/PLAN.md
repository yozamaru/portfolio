## 5. 作品データ（後から追加できる設計）

**1作品＝1フォルダ**。フォルダを追加するだけで、一覧・詳細ページ・タグ・OGP画像が自動で増える。

```
src/content/works/<slug>/
  ja.mdx      # 正（必須）
  en.mdx      # 英訳（任意）。frontmatter に sourceHash を持つ
  icon.png    # 作品アイコン（必須）
  screenshots/…
```

frontmatter は Zod のスキーマで検証し、必須項目が欠けていればビルドを失敗させる。

| 項目 | 必須 | 説明 |
|---|---|---|
| `title` | ○ | 作品名 |
| `tagline` | ○ | 一言説明 |
| `icon` | ○ | アイコン画像 |
| `status` | ○ | `live`（公開中）/ `beta` / `developing`（開発中）/ `archived`（停止中） |
| `url` | | サービスのURL |
| `repo` | | 公開しているGitHubリポジトリ |
| `category` | ○ | Webアプリ／ツール／API など |
| `stack` | ○ | 技術と、それぞれの役割の配列 |
| `screenshots` | ○ | 1枚以上 |
| `metrics` | | 見せたい数字（ラベルと値）。**今は使わない方針**（§7） |
| `decisions` | | 設計の判断（課題 / 検討した選択肢 / 選んだ方法と理由 / 結果） |
| `featured` | | 代表作フラグ |
| `releasedAt` | ○ | リリース日（並び順に使う） |
| `accentColor` | | 作品ごとの差し色（リンクやタグなど細部に使う） |

並び順は、代表作（`featured`）が先頭、あとは `releasedAt` の新しい順。

## 8. デザイン

- ミニマルで余白を重視したデザインを土台にし、作品ごとの差し色を組み合わせる。
- ブランドカラーは、2作品のアイコンに共通する**深い紺〜青とオレンジのアクセント**。
- 2作品とも青が基調なので、作品を見分ける主役は**アイコン**にする。`accentColor` は細部だけに使う。
- ライト／ダークモードを切り替えられる（初期値はOSの設定に合わせる）。
- 日本語／英語を切り替えられる。

## 9. 多言語対応の運用

- 日本語を正とし、英語は任意。英語版がない作品は、英語ページでは日本語を表示し「英語版は準備中」と注記する。
- メニューやボタンなどの画面の固定文言は辞書ファイルで管理し、日英の両方を必須にする。
- URLは日本語が `/`、英語が `/en/`。`hreflang` を設定する。
- **翻訳は下書きから運用まですべてAIが担当する**。作品を追加・更新するClaude Codeのセッションで、`ja.mdx` と `en.mdx` を同時に作る（追加のAPI費用はかからない）。
- **古い翻訳の検知**：`en.mdx` に翻訳元の `ja.mdx` のハッシュ（`sourceHash`）を持たせる。一致しない場合はビルドやCIで警告を出し、英語ページに「翻訳は日本語版の更新前のものです」と表示する。
- 更新頻度が上がったら、GitHub Actions＋Claude APIによる完全自動化に切り替えることを検討する。

## 10. 技術構成

| 領域 | 採用 |
|---|---|
| フレームワーク | Astro（Content Collections＋Zod） |
| 配信 | Cloudflare Workers（静的アセット配信と問い合わせAPIを同居させる） |
| デプロイ | GitHubへのpushで自動デプロイ |
| 問い合わせフォーム | Cloudflare Turnstile＋Workers → Resendで自分のメールアドレスに送る |
| アクセス解析 | Cloudflare Web Analytics（Cookieを使わないので同意バナーが不要） |
| OGP画像 | 作品ごとにビルド時に自動生成（アイコン＋名前＋一言説明） |
| リポジトリ | `yozamaru/portfolio` を公開。秘密情報は環境変数で扱う |

- 既存の2作品はNext.jsだが、このサイトはコンテンツ中心なのでAstroを選んだ。用途に合わせて技術を選べることを示す材料にもする。
- 運用費は年間0円（無料枠の範囲内）を目標にする。
